## 実行に使った接続

nanobindをインストールできなかったため、テスト・Notebook・再実験には **同じC++計算本体を呼ぶC ABI＋ctypesの検証用接続** を明示的に使用しています。これはPythonだけの代替アルゴリズムではありません。一方、nanobindの所有権やABIまで確認できる代替手段でもありません。

検証コマンドは次の形式です。

```sh
uv run --no-project --python /opt/pyvenv/bin/python python scripts/verify.py --offline-native --notebooks
```

この絶対パスは作成環境の実測記録です。利用者の環境でそのまま使う必要はありません。`--no-project` は既存環境を使うための指定で、プロジェクト環境の同期成功を表しません。

スキップした8項目は `tests/test_nanobind_contract.py` です。カプセルによる出力所有権、暗黙変換の拒否、読み取り専用入力、寸法不一致、幾何出力の有効性、不正数値の例外変換を対象にしています。通常のnanobind環境で実行するとスキップを解除します。

## 配布物の整合性

配布スクリプトはソース、文書、入力、結果、実行記録を選別し、ファイル別SHA-256を `MANIFEST.sha256` に収録します。zstd自身のストリーム検査と、展開後のハッシュ検査を実施します。別の場所への展開・再ビルド確認の結果は `reports/relocation.json` に保存します。

最終アーカイブのSHA-256は、アーカイブ自身を含む自己参照を避けるため、外側の同名 `.sha256` ファイルで提供します。再度実験を実行して計測値やNotebookの出力時刻が変われば、配布物のハッシュも変わります。再圧縮の同一性は、入力ファイルとzstdのバージョン・オプションが同じ場合に限ります。
