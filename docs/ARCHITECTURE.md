# 設計と計算の契約

## 依存関係と責務

利用側は `segment` などの小さな関数を呼びます。設定は `LatticeConfig` と `MergeConfig` の不変な値で表し、モジュール全体を書き換える状態は持ちません。公開APIが入力を検証し、特徴量の作成後にnanobindを通してC++17の計算関数を呼びます。画像の読込、書出し、表示は別のモジュールです。

`cpp/include/permutohedral/core.hpp` は標準C++の値・配列参照だけで構成する境界です。計算本体はPython、NumPy、画像形式、Jupyter、ファイルシステムに依存しません。`cpp/src/bindings.cpp` だけがnanobindとNumPy配列との接続を受け持ちます。PNG読込はPillow側に移し、旧版で必要だったlibpngをC++から除きました。

単一責任は幾何、連結性・併合、Python接続、入力検証、保存・表示を分けることで実現しています。任意特徴量のAPIにより、色空間などの変更を幾何本体の書換えなしで試せます。公開境界は必要な操作に限定しています。上位の入出力都合に計算本体を依存させません。継承を使わない設計のため、置換原則のためだけの基底クラスは設けていません。

SOLIDはクラスの数を増やす理由にはしていません。KISSに従って処理の流れを明示し、DRYに従って包含単体探索と画像全体の分割は一度だけ実装しています。コマンドライン、実験スクリプト、Notebookは同じ公開APIを使います。C ABIの検証用接続も同じC++関数を呼び、分割アルゴリズムは複製しません。

## 単体分割の定義

特徴量の次元を `D` とし、和が0となる `D+1` 次元超平面に配置します。従来実装の尺度正規化 `sqrt(2/3)*(D+1)` を維持します。フィルタ用の尺度慣習を残していますが、今回の処理では平滑化、splat・blur・sliceは実行しません。

位置のみでは `(sx*(x+0.5), sx*(y+0.5))`、RGBのみでは `(sc*R, sc*G, sc*B)`、両方ではその5次元の連結を使います。RGBは0～255です。特徴量を含む単体の頂点集合を辞書順に正規化してIDの鍵とします。これは最近傍の格子頂点への割り当てとは異なります。

単体IDは入力の走査順に0から密に付与します。画像では行優先です。生の単体IDは画像上の連結領域数を保証しません。位置だけなら三角形状の直接分割になりますが、色を含めると同じ単体IDが画像上で離れた位置に現れることがあります。

## 併合は任意の後処理

`MergeConfig` を明示した場合だけ実行します。最初に上下左右の4近傍で各IDを連結成分へ分け、領域の隣接グラフを作ります。接している領域対のうち、次のWard型の増分コストが小さい対を順に併合します。

```text
S = sqrt(画素数 / 目標領域数)
z(p) = [R/color_sigma, G/color_sigma, B/color_sigma,
        compactness*(x+0.5)/S, compactness*(y+0.5)/S]
cost(A,B) = nA*nB/(nA+nB) * ||mean_z(A)-mean_z(B)||^2
```

統計量の合計と画素数を更新し、古い候補は版番号で無効化します。同コスト時は領域番号で優先順位を定めます。合併対象は隣接した連結領域に限るため、連結性を維持します。目標数は1以上、初期連結成分数以下でなければなりません。小さい初期領域からさらに細分化して数を増やす処理はありません。

これは貪欲な隣接併合です。大域最適解、物体単位の分割、SLICとの同等性は主張しません。格子の `color_scale` と、併合の `color_sigma` は別の尺度です。

## 配列・所有権・エラー

Python公開APIはRGBをuint8に限定します。ラベルは非負の整数でint32に収まるもの、任意特徴量は有限の実数で1～8次元を受け付けます。非連続配列は公開API側でC連続配列へ明示的に変換します。nanobindの内部APIには型と連続性を厳密に指定し、暗黙変換を無効化しています。

C++への入力配列は呼出し中に所有元を維持します。別スレッドから同じ入力メモリを書き換えないでください。出力はvectorを保持するカプセルを所有元とするNumPy配列として返し、Python公開APIで読み取り専用にします。C++計算中だけGILを解放する実装です。**このnanobind固有の所有権・型変換・GILの実動作は、今回の環境では未検証です。** 境界テストは `tests/test_nanobind_contract.py` にあります。

0画素、不正な次元、NaN/無限大、過大な格子座標、負のラベル、不一致寸法、不正な目標数や尺度は例外にします。画像および特徴量の点数は2千万まで、頂点を全て返す幾何確認は10万点までです。この上限は安全な添字計算のためであり、最大入力が少ないメモリで動くという保証ではありません。特に高次元で多数の成分が生じる場合、辞書・隣接グラフ・候補ヒープのメモリを多く使います。

NPZを読む際はpickleを許可せず、メタデータの版・寸法・領域数を検証します。画像はデコード前に寸法上限を確認します。透明部分は白に合成し、EXIFの向きを反映します。これらの境界ケースはPythonテストに含めています。

## 検証専用の接続

`tests/native/bridge.cpp` と `tests/support/native_adapter.py` は、取得できなかったnanobindとは別の検証接続です。`--offline-native` を指定した検証スクリプトだけが有効化し、通常APIが自動的に切り替えることはありません。wheelにはインストールしません。

この接続で確認できるのはC++計算、Python側の検証・構成・保存・表示です。nanobindのビルド、NumPyとの境界、カプセル所有権、ABI互換性を確認したことにはなりません。
