# 作業記録 — 2026-09-27

## 依頼と対象

前回のpermutohedral latticeによるC++画像領域分割を、nanobind・uv・Jupyter Notebookを使う構成に整理し、可搬性と管理性を考慮したソース、検証、作業記録をzstd圧縮で引き渡す作業です。前回の数値結果を変更するアルゴリズム改良は目的に含めていません。

入力はユーザー提供の `permutohedral_segmentation.zip` と `probreg-master(2).zip` です。元アーカイブと旧C++ファイルのSHA-256を `reference/provenance.json` に保存しました。無関係なprobreg全体は再梱包せず、今回の継承に必要なコード・通知と旧版の記録を保持しました。

## 実施内容

### 1. 元実装と比較基準を確認

単体への直接割り当てと隣接領域併合が別の操作であることを維持しました。ピーマンと牛の11条件ずつ、計22条件の旧版ラベルを基準データとして保存しました。旧形式はlittle-endian uint32の生バイナリだったため、寸法を保持したint32 NPZへ変換しました。ラベル値を変えていないことを確認し、変換方法を記録しました。

### 2. C++17の計算と入出力を分離

単体幾何を `lattice.hpp`、画像全体の割り当てを `lattice.cpp`、連結成分と隣接併合を `regions.cpp` に整理しました。外向けの計算契約を `core.hpp` に限定しました。PNG読込・表示・コマンドライン処理をC++から外し、標準C++だけで単体テストを実行できるようにしました。元のBSD通知を保持しました。

幾何の有限値、過大な座標、画像の画素数、ラベルの値域、目標領域数などの境界を検証する処理を加えました。元コードの正規化、画素中心、走査順、併合コストと同値時の順序は維持しました。

### 3. nanobindとuvの構成を追加

NumPy配列を受け渡すnanobind接続を `bindings.cpp` に実装しました。C連続・CPU・型の制約、暗黙変換の禁止、vectorを保持するカプセル、C++計算中だけのGIL解放を記述しました。公開APIの型情報を `.pyi` と `py.typed` に含めました。

ビルドはCMake＋scikit-build-core、環境定義は `pyproject.toml`、開発Pythonは `.python-version` にまとめました。通常依存、開発用、Notebook用の依存を分離しました。公式資料でnanobind 3.1.0とscikit-build-core 1.1.0を確認し、ビルド用直接依存を固定しました。

**この環境で `uv sync --all-groups` を実行しましたが、PyPIへのDNS解決が失敗しました。** 記録は `reports/logs/uv-sync-attempt.txt` です。nanobind、scikit-build-core、Ruff、mypyを導入できず、`uv.lock` も生成できませんでした。公式GitHub経由で文書・通知を参照できましたが、依存パッケージのローカル導入には至っていません。未解決のロックファイルを手書きしたり、未ビルドのwheelを作成済みと扱ったりしていません。

### 4. 検証範囲を明示した接続を追加

計算の確認を止めずに進めるため、同じC++本体をC ABIで呼ぶ **検証専用** の接続を `tests/` に置きました。`--offline-native` を指定したときだけ有効にし、通常のnanobind経路に自動的に切り替わる代用品にはしていません。wheelへのインストール対象にもしていません。

この方式で確認した対象と、確認していないnanobind境界を分離しました。後者の8テストは明示的にスキップし、Notebookの先頭出力、実験一覧、検証一覧へ実際の接続方式を保存しました。

### 5. Python API、実験、Notebookを共通化

設定を不変のデータクラスにし、画像の型・寸法検証を集約しました。CLIとNotebookは `segment` など同じAPIを使用します。計算部分をNotebookへ複製していません。可視化、PNG入出力、NPZラベル、JSONメタデータは計算と別のモジュールにしました。

22条件を `experiments.toml` に集約しました。Notebookは位置だけ、色＋隣接併合、幾何と計測の3冊に分けました。実行器は一時的なカーネル定義を使い、利用者の全体設定やカーネル登録を変更しません。編集用のNotebookと実行済みのNotebookを分けて保存しました。

### 6. テストと補強

初期確認後、単体の不変条件、独立した連結成分の比較、寸法・型・値域の異常、単一画素、入力を変更しないこと、出力の有効性、並行呼出し、保存と読込、CLIの正常系・異常系を整備しました。最後に、画像のデコード前の画素数上限と、結果メタデータがJSONオブジェクトであることの確認を加えました。

現行の検証結果は **121合格・8スキップ**、旧版22条件は **全画素一致** です。3冊のNotebookをそれぞれ新しいカーネルから実行しました。実行した正確な時刻・コマンド・終了コードは `reports/verification.json`、検査結果は `reports/pytest.xml` にあります。旧い `pytest-offline-native.txt` は途中時点の118件の記録であり、最終集計ではありません。

C++の幾何検証は1～8次元の各10,000点、計80,000点です。最大復元誤差は2.27374e-13でした。GNU Releaseに加え、GNUのASan/UBSan付きDebugとClang ReleaseでもC++単体テストを実行しました。実時刻は2026-09-27 11:07 UTC台、詳細は `reports/native-variants.json` にあります。これはPython拡張の検証ではありません。

### 7. 管理・配布用の資料を整備

README、設計、可搬性・環境管理、検証結果、出典、第三者通知を追加しました。GitHub Actionsには3OS×3Python版の設定を置きましたが、今回外部サービス上で実行していません。依存ロックを作成してコミットする初回手順を記載しました。

実行環境は必要なソフトウェア名と版だけを記録し、環境変数全体や認証情報を収集していません。既存の `.venv` やビルド結果は成果物に含めず、別の環境で再構築する前提にしました。同梱画像については、新規コードのライセンスと区別しました。

### 8. 圧縮・展開の確認

`package_release.py` を追加し、必要なファイルだけを選択してtar＋zstdで圧縮します。tarの順序・時刻・所有者・モードを固定し、ファイル別のSHA-256を同梱します。zstdのストリーム検査と、展開後のファイル整合性検査を行います。

別の空白を含むパスに候補アーカイブを展開し、ソースの再ビルドとテストを行う手順を採りました。展開後のSHA-256照合、C++の再ビルド、CTest、Pythonテスト121合格・8スキップを確認し、実結果を `reports/relocation.json` に保存しました。最終圧縮物のハッシュは外側の `.sha256` です。アーカイブ自身のハッシュをアーカイブ内部に自己参照で埋め込むことはしていません。
